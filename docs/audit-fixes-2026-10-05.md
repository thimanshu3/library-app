## Completion batches — 5–6 October 2026

The owner requested all remaining repair batches in one run and explicitly excluded new test cases. The sections above describe the earlier batch-one state; the following disposition supersedes its remaining-work list. The nine new-feature suggestions remain suggestions.

### Persistence, data model, and workflows

F01–F09, F14, F15, F17, F18, P02, P04, Q01, and Q03 received code fixes. Focused mutations replace whole-loaded-library saves. Only explicitly selected copies are deleted; deleting a copy retains the Work catalog. Work changes use their own revision, so editing a later copy updates shared metadata and rejects stale edits. Copy row locks and revision checks protect edits, loan history, and reader events. New drafts have stable UUID creation tokens and stored fingerprints; identical retry submissions return the original copy, while changed retries conflict rather than creating a second copy.

Manual title/author editing, shelf replacement, reading start/completion dates, tags/collections, private notes/reviews/quotes, ownership, currency, lend/renew/return, and persisted annual goals are wired to those mutations. Errors keep the draft open and success follows the commit. Canonical shelf fields replace mismatched editor fields. Returned loan history cannot be removed by a stale editor. Reader sessions use stable IDs and cumulative measured minutes; retry updates take the maximum duration and newer progress timestamps, preserving independently recorded history. Batch marking as Read skips already Read copies so repeat clicks do not rewrite their completion dates.

The versioned baseline/additive migrations preserve existing Works/Copies while introducing Edition, relational ReadingSessionRecord and Loan, Attachment, and LibrarySettings models. Money uses Decimal and event dates use database calendar dates. Ownership is independent of reading/lending state; legacy fields remain for migration compatibility. Numeric publication-year and library-order columns support correct ordering. The legacy-history script is repeatable and retains original JSON. It migrated two sessions and zero loans in this installation with no invalid events reported. The later creation-token migration is applied too.

Price offers now have their own amount/currency/time/source and never replace acquisition cost. Google Books lookup moves to an authenticated, bounded server route with an optional server-only key. Enrichment is keyed to the requested title/author/ISBN, buffered if it arrives before the editor opens, and fills only unedited empty fields. Book description conversion uses an inert parsed document and returns text only, rather than assigning provider HTML to an ordinary element. [MDN describes the inert parsing behavior and the risk of inserting parsed nodes into an active DOM](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString); no parsed nodes are inserted here.

### Full-library queries, import, and client performance

F07, F10–F13, F16, P01, P03, P05, Q04, Q05, and Q07 received code fixes. Listings use validated Prisma filters, database ordering, bounded pages, and cursor ties on Copy ID. Full-library operations explicitly read in 250-copy database chunks under one consistent snapshot. Analytics, loans, wishlist price checks, export, duplicate lookup, and complete facet options no longer depend on scrolled pages. Filters share desktop/mobile contracts, include canonical shelves and custom genre/volume values, reset pagination when changed, and persist through URL history. Aborted/obsolete requests cannot append to another filter's results.

JSON v2 and CSV export the complete Book DTO and annual goal. CSV includes a quoted JSON record column to retain all metadata/history; readable text columns are spreadsheet-safe. Import handles those exports, older grouped JSON, and mapped Goodreads CSV, reports row errors, and merges new copies without overwriting existing ones. Files are capped at 20 MB, requests at 25 rows/about 700 KB, and copy identities make retries safe. Existing-ID lookups are batched once per request to keep repeated large imports efficient. These exports reference private ebooks rather than embedding their bytes; a validation/registration command supports copied ebook references before importing into another installation.

The main client delegates query coordination, theme, dialogs, and reading persistence to hooks. Optional charts, camera scanning, readers, import parsing, and image capture load when requested. Card/list/detail/analytics selectors share actual page progress and measured activity rather than fabricated percentages or estimated reading hours. Heatmap includes today, counts unique active dates, and avoids repeated nested aggregation. PDF bundles the matching local worker, fits the viewport, and saves page counts/progress. EPUB persists CFI and disables ebook scripts/popups; embedded content interactions refresh the idle timer. Timers checkpoint device recovery state each second, save periodically, pause while hidden/unfocused, and keep the reader open on failed close. Acknowledged progress can close even when browser storage is unavailable.

Responsive cover components (including decorative blur layers sharing the lazy optimized image URL), a common cover resolver, a protected allowlisted share-image proxy (including validated Open Library/Internet Archive cover-collection redirects), visible download errors, live theme updates, reduced motion, keyboard card access, dialog focus containment/return, form labels, mobile shelf filtering, and announced status/errors address the UI findings. Nested dialogs restore body scrolling correctly. Calendar labels and loan-day calculations avoid timezone/DST shifts. Unused axios/glob/config dependencies and confirmed starter assets were removed; EPUB and ZXing peer dependencies remain. The blanket any lint exemption is removed; full-project lint passes with no warnings.
